审查日期：2026-10-25（北京时间）。源码基线：main `c1f139559f63e862554c768961cad8d9698cc201`，审查开始时工作区干净。

本次仅阅读源码、文档及公开插件包；没有安装、导入或执行插件，没有读取运行配置/聊天数据，没有调用模型、发送QQ消息、部署或重启。本文件是唯一新增文件。以下运行表现和节省幅度属于待验证推断，不冒充线上测量。

## 结论

1. 当前项目有相近的成本控制基础，但**没有通用的按本轮话题选择 Skill 说明和工具的功能**。已有功能开关/场景过滤、省 Token 上限、跨对话回忆的相关性筛选与生命周期去重，不能等同于该插件。
2. 插件思想值得借鉴，**不推荐直接安装，也不推荐为它补齐整套上游 Skill/hook/provider 框架**。公开源码已取得，兼容性障碍可以明确定位。
3. 推荐三种方案中的“改进现有功能”：在现有提示词/工具组装入口加入默认关闭的、结构化的能力选择模块。参考插件的保守默认与短期保留思路，重新设计生命周期策略；先观测、再小范围试验，不承诺固定百分比节省。
4. 当前没有批准开发或上线；本报告不触发后续动作。

## 插件算法与兼容性

其算法为纯本地规则，无额外模型分类调用：

1. 固定触发词表覆盖 12 个技能 ID；不在表中的技能和无法归属的工具默认保留，可另设常驻名单、追加触发词及私聊全部保留。
2. 从第一个字符串 user message 中切取两个特定标题下的内容，转小写后做子串匹配；不是语义分类，也不使用结构化最新消息。
3. 命中关键词或调用技能工具后，按 chatKey/skillId 保留默认15分钟；状态仅在内存，重启丢失。命中本身就会延长保留，不要求工具调用成功。
4. before-llm-messages 从系统提示中替换同源说明段字符串；after-tool 更新保留状态；llm.request-params 转换器过滤请求 tools。内置工具不裁。
5. 统计删除的字符数/工具数，不是 tokenizer 计数，也没有真实账单或任务成功率统计。

直接安装有三层独立障碍：

- 原生插件 manifest 声明 `llm.request-params`，不在宿主能力白名单中，且没有必需的非空 tools 清单/原生 activate 契约。
- 经市场兼容层导入会遇到三个不存在的上游模块；即使改好 import，setup 不注册任何工具仍被判失败。
- 宿主根本不调用它导出的 hooks/providers，说明段格式也不同：插件使用 `▸ 标题` 模板，当前使用 `【标题】`；消息标题亦不应假设一致。单纯改路径或绕过审批不能使其生效。

插件原触发词表主要对应另一套宿主技能 ID；本项目大量功能为内置工具，照搬规则可能几乎没有收益。把内置工具改成上游 skillId 则会扩大语义变更范围。

## 收益与风险

### Token 与费用

潜在收益来自少发无关说明段和工具 schema；同一次运行有多次模型请求时，重复输入也会减少。只有本来就实际注入、且允许裁剪的内容才能产生收益。原包注释中的字符量/工具数是作者环境，不是当前项目数据；省 Token 模式注释中的旧线上测量也不能当作今天的基线。

粗略净输入变化可写为：各调用省掉的说明/工具 token 总量，减去新增目录/选择结果/恢复调用及线程重建增加的输入。费用还要分别计算缓存命中与未命中单价；字符数不能直接等同 token。

应先分层测量 system 基础、人设、可选说明、工具 schema、动态记忆/历史、工具输出，以及实际 promptTokens/cachedTokens/calls/费用。纯闲聊、混合任务、多轮追问、长 lifecycle 必须分别比较。若可裁部分很小或缓存损失抵消收益，应保留现状；本次未读取聊天日志或做线上 A/B，因此没有可信节省百分比。

### 漏选、误选与一致性

- 隐含需求、别名、引用回复、图片消息、“继续/第二个/发原图”等可能没有触发词；工具完全隐藏后模型无法自行调用补救。
- “画”“mod”等宽泛子串可能误中，群聊引用和其他人的话题也可能不相关。恶意堆词可让许多技能持续保留，减少收益；选中能力绝不能授予权限。
- 15分钟是时间保留，不是任务生命周期：慢速追问会过期，重启会丢状态，活跃群又会长时间保留多数技能。
- 第一个 user message 不一定是最新触发批；lifecycle 中旧 transcript 更容易造成对旧文本决策。
- 插件将说明替换与工具过滤分两处独立执行，匹配说明失败时仍可删工具；说明和实际工具可脱节。try/catch 不会自动撤销此前原地修改，也不保证行为等同插件关闭。
- 字符串全局替换只取首个匹配位置，缺少结构化归属校验；相同文本碰撞时不能宣称绝不误删。代码注释称 reply-meme 常驻，实际触发词表却包含它，行为应以表为准。

### 生命周期与缓存：主要阻碍

当前 `orchestrator.js:1847–1864` 将 systemPrompt、OpenAI tools、模型/渠道及回忆策略纳入 promptPrefixHash。活跃 lifecycle 线程的 hash 不同就以 `prompt-prefix-changed` 关闭，旧 provider transcript 不再按原路径继续。

逐轮裁剪说明/工具会改变 hash，因此可能增加线程关闭、上下文重建、回忆重新注入与缓存未命中，影响多轮连续性。这是代码能确定的触发路径，损失幅度尚未实测。

若仿插件在哈希、审计和预算估算之后才偷偷修改请求，会让记录/估算/hash 与真正发送内容不一致；不能靠这种办法绕过生命周期约束，也不能简单删除 hash 校验。

### 安全与数据

公开包两份文件中未见网络请求、文件写入、删除数据、模型调用或主动QQ发送；这是静态审查结果，不是隔离执行认证。它读取配置和提示上下文，直接依赖上游内部模块。同进程 JS 不受能力清单形成的进程级沙箱约束，`permissions: []` 也不代表没有影响力。

宿主市场审批 digest 覆盖清单字段，不覆盖入口源码完整内容；市场 approved 标记也不能代替源码审查或内容校验。未来引入第三方包仍需固定内容哈希和来源。

## 三种方案比较

| 方案 | 收益与代价 | 判断 |
| --- | --- | --- |
| 直接安装 | 当前接口不兼容，补全上游 hooks/providers/skills 会扩大可信代码面；原规则 ID 不适配 | 不选 |
| 参考源码新建独立原生系统 | 可定制，但重建 Skill 管理、配置和生命周期会与现有注册表重复；复制代码还需许可核实 | 不建设完整第二套系统 |
| 改进现有功能 | 复用工具过滤、提示词注册、tokenSaver 和用量记录；只新增能力选择策略及观测 | 推荐，独立模块拥有配置/状态，选择结果由两条组装链共同使用 |

第三种方案也需要原生代码开发；区别在于扩展现有链路，不把市场插件当运行依赖，也不替换人设/记忆/会话系统。

## 后续实施建议（等待批准）

1. **先做测量与影子决策。** 默认关闭，开启观察也不删除任何说明/工具；基于结构化 triggerEntries、引用和当前任务状态计算。仅记录模块ID、选择原因、字符量估算等脱敏标量，不另存聊天原文、不增加分类模型调用。
2. **定义可选能力元数据。** 显式 ownerId、工具集、说明段、依赖、触发规则和常驻类别；基础人设、安全/管理员身份、发言/finish、隐私、历史查证纪律保留。未知归属、规则异常、不确定场景保留原集合；已禁用/越权能力绝不因选择而重新启用。
3. **先在 legacy 的低风险说明段试验。** 初期保留工具定义以降低漏选损害，用同一选择计划在渲染前决定段落；不对成品系统提示做字符串删除。若测量显示说明收益太小，可停止；不为追求数值直接扩大裁剪。
4. **再评估工具裁剪。** 同轮工具集稳定；工具依赖和最近有效任务共同保留，显式能力名与能力发现/恢复路径避免隐含追问永久失去能力。发现工具仍需原权限检查和有界往返，计入费用。插件工具继续按保守串行调度，不自动改为并行。
5. **单独设计 lifecycle。** 第一版 lifecycle 不实际裁剪，只观察。后续若需要，在线程边界确定集合并固定版本，记录与 checkpoint 同步的最小模块状态；新能力扩展须有明确的安全切换/上下文承接流程。不能逐轮随TTL缩回集合，不能关闭原hash与隐私失效保护。threaded、重启恢复亦需专门验收。
6. **分阶段验收。** 普通闲聊、显式/隐含请求、图片/引用、继续与翻页、多技能依赖、15分钟外追问、重启、权限变化、跑团与主动私信、工具失败及结果未知、说明/工具一致性、lifecycle hash/回忆去重与审计预算一致性。衡量漏选率、任务完成率、延迟、调用数、缓存率和总费用，不能只验删了多少字。

## 数据保留、关闭与回滚契约

- 只增加独立配置命名空间及最小策略状态；旧配置默认关闭，不重写 tokenSaver 用户值，不关闭既有技能开关；不迁移、清空或改写人设、memory、messages、sessions、账号白名单及原功能配置。
- 模型可见性仅在现有允许集合内做选择；不把裁剪当作权限边界。跨对话隐私、游戏秘密过滤及外发 outbox/unknown 规则原样延续，不自动重放或重试历史任务。
- 关闭立即停止新选择，保留设置和观测数据，后续运行回到原组装入口；在途请求采用版本固定/安全结束，不能热改已发请求。
- lifecycle 从试验恢复全量集合也可能改变前缀，需安全关闭并承接新线程，不能承诺原 provider transcript 字节级无感恢复；原聊天数据与检查点必须保留。
- 上线前验证源码回滚与新增配置被旧版忽略的行为，保留原配置和数据库备份，禁止用整份旧配置覆盖后续用户修改。回滚不会撤回已经发生的QQ外发，也不能删除数据来“恢复”。
- 若作为实验功能，实现须遵守 `docs/EXPERIMENTAL_FEATURE_STANDARD.md`：enabled 与 graduated 独立；有操作/观测界面时归独立页面；禁用不删数据。
- 本机验证遵循交接中的384MiB Job/128MiB Node堆、单进程串行约束；UI修改再按 AGENTS 执行相应用例和烟测。实际外发验收另需用户授权。

当前建议停在本审查结论：先由用户决定是否开展测量/影子模式开发，不安装原包，不自动部署。
