# 诡秘战术长期战役

本模块提供22条途径的序列9—5自建角色、按玩家隔离的编号选择、小型方格战斗和持久成长。规则为项目自定义d20适配；每个序列节点提供一个明确限幅的新增能力，之前的能力保留，共110个节点，不宣称复刻原著全部能力或完整COC/DND规则。

本页仅适用于明确选择 `lotm-tactical-v1` 的诡秘世界。其他题材使用通用叙事模式，建角按当前世界的职业和背景进行，不带入诡秘途径和资源；见 [按世界建角](TRPG.md#按世界建角)。

## 一分钟开始

1. 控制台「跑团」开启功能，保存允许的群号或私聊QQ号。名单为空禁止该类会话开团，全局授权与运行时段仍然有效。
2. 团主在QQ发送 `/跑团 开团`，默认使用内置灰堤长期战役；也可指定网页保存的战术世界ID。
3. 每名玩家发送 `/跑团 建角`。按编号选择途径，输入姓名与背景，再选属性方案并确认。草稿按会话和QQ隔离，重启保留；在待开始/非战斗暂停的战术团内创建后自动加入。
4. 团主发送 `/跑团 开始`。各自回复自己的行动序号，也可以自由描述。

每名玩家控制一张卡。已有网页卡可用 `/跑团 加入 角色ID`，战术角色必须有合法途径；缺少途径的旧角色可继续玩原有叙事团，或编辑模板后另开战术团。修改模板不替换已加入角色。

可导入示例：[战术世界](examples/trpg/tactical-world.json)、[战术角色](examples/trpg/tactical-character.json)。无需模板也可直接QQ建角。

## 编号与群聊节奏

- 探索为每位在队且未倒地的玩家维护自己的菜单。同一个“1”按发言者QQ解释，不使用其他人的菜单。
- 菜单显示短ID；单发序号使用当前菜单，也可发“菜单ID:序号”避免误选已更新菜单。场景切换会生成新菜单，旧ID拒绝。
- 数字只有在合法菜单中有意义，错误数字不作为另一项自由行动执行。自由描述不必加前缀或@。
- 探索收集本轮全体意图后交给主持。已经提交不能重复扣费；同一时段多人并行取最长游戏耗时，不逐人相加。
- 裁判尚未结算时不接收下一轮选择，避免覆盖已有行动。回复失败可发“继续结算”，保留原骰点和消耗；自由战斗意图也可用此恢复，或 `/跑团 菜单` 取消尚未执行的意图后重选。
- `/跑团 待命` 明确提交等待；`场外：问题` 或 `规则：问题` 不推进时间，也不允许规则工具趁机发奖或开战。
- `/跑团 暂离` 在非战斗时暂离，角色和成长保留，不再阻塞全员选择；`/跑团 归队` 恢复。战斗中不切换在队状态，可由团主暂停整团。
- 当前游戏窗口不使用普通聊天人设，不安排普通主动补话；群聊自主节奏不延迟已经提交完的跑团行动。全局预算与活跃时段继续生效。

## 战术战斗

默认8×8，可建4—12列、6—12行战场。A1式坐标，每格为抽象战术距离，不固定换算原著米数。界面显示蓝色玩家、红色敌人、墙/门、掩体、危险格与互动物。QQ同样提供文本地图和编号菜单，移动目标无需手输坐标。

每回合一次主要行动、一次辅助行动、默认移动3格；移动可拆分，剩余点数由程序记录。按真实d20先攻加敏捷决定顺序，同值用稳定ID排序。程序依序执行敌人回合，玩家不能提前替另一名玩家操作。

| 项目 | 执行规则 |
| --- | --- |
| 移动 | 四方向寻路，不穿墙、关闭门或站立单位；减速格多耗一点移动，进入危险格扣实际HP |
| 视线 | 墙/关闭门阻挡；两侧墙夹住的斜角也不能穿射 |
| 普通攻击 | 近战1格；有枪/弓/弩且有弹药可远程4格；主要行动，d20+力量/敏捷，对方防护与掩体参与比较 |
| 伤害 | 玩家普通命中1d4，能力伤害加能力威力；敌方采用建立战斗时公布的固定伤害，攻击仍真实掷骰 |
| 掩体 | 等级1/2，提供防护+2/+4；临时防护按能力单独结算 |
| 非凡 | 必须已解锁；检查主要/辅助额度、灵性、距离、视线、目标阵营、落点及能力限制 |
| 加值 | 同类临时攻击加值取最高值，不无限叠加；攻击/下一回合到期时移除 |
| 控制 | 对方真实豁免；失败限制下一回合行动，不强迫玩家人格或队友立场 |
| 范围 | 波及范围内单位；包含友军时必须在菜单上明确，或由自由行动者明确确认友伤 |
| 物品 | 绷带/治疗药剂一个文本条目代表一个可消费单位，辅助行动恢复3HP并移除该条目；数量不解析成隐含无限使用 |
| 环境 | 相邻互动需主要行动：开普通门、关危险灯、建立掩体、救援环境目标；对应标记写入战役 |
| 撤离 | 在地图边缘可撤出自己的单位，任务不自动完成，未撤出的队友仍需行动 |
| 全队倒地 | 可选择求援，花一游戏小时带回安全处，恢复到至少1HP并记录负伤/援助事项；不抹掉原任务失败或未完成事实 |

战斗菜单为：1攻击、2非凡、3移动、4更多。进入后继续按编号选技能、位置或目标；更多里有物品、环境、防御、结束回合与边缘撤离。合法性在执行时再次检查，过期选项不会突破规则。部分能力需要特定掩体/门/已见攻击；没有条件时应换方法。

枪械每次攻击消耗独立的“子弹”条目，弓弩消耗“箭矢”，未命中也消耗；物品批量数量需展开成独立条目。程序不提供精确先攻反应、无限自由施法、完整枪械机制/货币经济、任意新装备词条或原著所有高阶领域；这些不应被主持口头当成已经实现的系统。武器名称只选择本引擎内的近/远程规则，不读取文本中的“攻击+999”。

## 探索与非凡

普通自由行动由主持解释，需检定时用专用探索检定工具，检查属性与难度，保存一次真实结果和耗时。已经通过编号结算的行动不可再掷。新伤害风险先说明、获得确认；不能从没有接受风险的自由描述直接扣生命。

`/跑团 能力` 显示已经解锁的能力、消耗和边界。部分探索能力直接结算；穿门和短距旅行先要求主持核对实际目标，使用规则工具检查普通门类型/厚度、已知落点或距离后才支付与检定。战场控制、伤害和其他必须有目标的效果在战场执行。

防护能力只用于战场；鼓舞、隐匿、冲刺在探索中启动成功时转为下一次相关检定+2，仍须符合能力描述的叙事情境。一次非凡行动不再通过普通探索检定额外重掷。

灵性初始6，序列每升一级上限+2，最多14。每次主动能力增加本段过度使用计数，第4次起每次污染额外+1；灵性不足或污染6不能主动施术。污染6限制战斗主要行动和移动，仍可选择结束回合/撤离/求助，不自动强迫伤害队友。

安全休整须所有在队玩家选择相同时长：1小时灵性+1；8小时灵性回满且HP+2；均不超过上限，重置过度使用计数。污染每天最多通过看护休整降低2点，按游戏日记录。休整不清空关系、消化或任务。游戏时间推进，若危险源尚未暂停，危险累计也推进。

## 长期成长

初始序列9，只能原途径逐级晋升至5。人物基础HP10，每级上限+2；消化目标依次6、8、10、12。各序列节点有一个新增的同人能力条目，保留已学能力；可在控制台目录与角色能力菜单查看。

消化由主持依据有实际意义的行为给出证据，程序限制同一场景一次、同章最多两次，记录事件与理由。已经发放不能因换checkId或暂停继续而重领。章末安全处至少完成一个新的任务日志目标，团主才能 `/跑团 下一章`；没有新目标不能刷章。

晋升需要：

1. 活着，在无战斗、无待结算意图的安全场景。
2. 消化达到当前目标，污染≤1。
3. 取得下一序列的配方、对应材料包；目标序列5还须有已完成仪式记录。
4. 本人发送 `/跑团 晋升`，查看清单后回复1确认。

材料包在尝试时消耗，真实d20+感知对难度12/13/14/15（晋升8/7/6/5）。成功降序列、消化归零、HP和灵性上限各+2并增加相应可用量；失败保留序列与消化、材料消耗、污染+2。配方、材料和仪式使用抽象准备记录，不提供虚构的原著精确化学配方。不能任意跳级、换途径、直接导入序列5或让模型代玩家确认。

任务日志、NPC位置/态度/经历、成长证据、共有事件和累计剧情持续保存。NPC和奖励的剧情依据仍由模型主持判断；程序负责类型、上限、去重、实际消耗与数值计算，并不能证明模型对原著或剧情的判断永远正确。

## 保存、退出与升级

“退出游戏”与“退出跑团”现在表示保存暂停。团主“继续跑团”恢复同一场景、菜单、待选意图、战斗回合和资源，现实离线不推进时间。正式归档使用“结束战役”，再 `/跑团 确认结束`；控制台的结束操作也有确认。

数据仍在 `<dataDir>/trpg/state.json`，格式升级到version2。首次读取旧version1只在内存补默认值，不立即改文件；第一次成功写入前自动备份原件为 `state.json.v1-随机ID.bak`。旧团不自动变成战术团、不清资源，继续原规则；可以保留旧团并在另一会话另开战术团，或结束旧团后新开。

部署须保留整个数据目录。需要回退旧宿主时，应先停用服务并额外备份当前version2文件，再恢复升级前的v1备份；旧宿主不能直接读取version2。恢复v1会回到备份时的进度，不能同时保留升级后新增长期战役。没有v1备份的新战役应保留当前文件，等待兼容宿主恢复，不能用空文件覆盖。

## 模块与验证

`catalog.js`定义110节点与数值；`combat.js`执行空间/战斗；`adventure.js`执行向导/编号/成长；`manager.js`负责权限、原子存盘、备份和模型工具；认证API与独立工作台仍由跑团模块拥有。

专项：`node --test test/trpg*.test.mjs`。使用临时目录、真实管理器/前端导入方法与模拟模型/OneBot事件，覆盖QQ隔离、去重、晋升、合法性与恢复；未连接生产QQ或付费模型，线上完整自然语言战役仍需试玩。
