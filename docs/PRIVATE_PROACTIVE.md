# 主动私信适配

`plugins-silence-ping.zip` 来自另一套插件系统，依赖 `setup`、`hooks`、`providers`、后台定时器及宿主内部文件。当前插件 API 只允许注册模型工具，不能安全地直接装载。这里将其核心的主动私信筛选规则接入宿主调度器，保持与群聊主动发言独立。

## 启用

在控制台「设置 → 聊天 → 主动私信」勾选总开关。默认仍处于**演练模式**：每次醒来只记录符合条件的私聊对象，不调用模型，也不会发送消息。确认日志中的对象范围和时间正确后，再关闭演练。

只有同时满足以下条件的会话会被考虑：

- QQ 在**私聊白名单** `allow.private` 中，且此前已有私聊记录。即便全局设置允许空白名单，主动私信仍要求显式私聊白名单。
- 若填写「指定 QQ」，还必须在指定列表中；无效的非空列表不会退化成全白名单。
- 当前为 active 模式，服务未暂停，会话没有未读、未知发送结果或正在执行的任务，模型与每日预算允许运行。
- 不在睡眠或工作勿扰时段；对方达到冷场门槛，最近未发言；机器人最近未发言。
- 前一次主动私信未获回复时不会再次主动发送。对方回复后，个人冷却随之解除，但仍需重新满足冷场门槛。

时间按北京时间判断。空「指定 QQ」只表示私聊白名单中的已有会话，不表示任意 QQ。对象可以写成 `123456789:60/180`，分别表示该 QQ 的冷场门槛 60 分钟、冷却 180 分钟。

成功发送后，每个对象的最后主动消息 ID、时间及当天消息数写入 `data/private-proactive-state.json`。这是服务器数据，不随 GitHub 代码更新覆盖。插件 zip 中的 `data/silence-ping.json` 不参与此功能。

## 与原 zip 的差异

- 由现有 `Orchestrator.wake()` 调用模型并走正常发送队列；没有读取 SnowLuma 令牌或直接请求 OneBot。此类唤醒只给模型 `send_message` 和 `finish`，每轮最多一条 300 字文本。
- 使用宿主现有的人设、上下文窗口、预算与发送保护。一次主动机会可能由模型决定不发；演练模式只验证本地筛选，不运行 AI 判断。
- 网页里的“主动私信补充要求”会加到该轮唤醒提示中，最多 120 字。
- 原插件的 `personaMaxChars` 尚未移植：宿主统一的人设裁剪策略仍然生效。`status.silence-ping` 提供者与原插件的专用状态面板不适用于当前宿主。
- 主动私信这一轮不会再安排通用“没人接话就补一句”，避免绕开“未回复不追发”；普通私聊与群聊的补话行为不变。模型自己安排的唤醒和定时提醒仍是宿主独立功能。

关闭总开关会停止下一次主动私信调度，不删除状态文件。重新打开后会沿用每日计数及各人的未回复记录。
