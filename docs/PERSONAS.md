# 内置角色卡

## 角色卡来源

内置角色卡正文统一存放在 [`roles/`](../roles) 目录，一张卡一个 markdown 文件。
`src/personas.js` 只做登记（id 到文件、显示名与语气档位），用相对模块 URL 读取，
不依赖启动工作目录。部署时必须带上 `roles/` 目录，完整同步会包含它。

| id | 名称 | 语气档位 | 定位 |
| --- | --- | --- | --- |
| `xiaojingyu` | 小鲸鱼（默认） | 原版群友 | 默认人设，傲娇嘴硬的群友腔 |
| `duzui_sunyou` | 损友（毒舌吐槽） | 原版群友 | 短句接梗，只损能开玩笑的事 |
| `wenrou_peiliao` | 温柔陪聊（知心） | 自然可靠 | 会听、不诊断、不承诺陪伴 |
| `jishu_zhai` | 技术宅（自建服务） | 自然可靠 | 先问关键信息，猜测与结论分开 |
| `maoniang` | 猫娘（二次元） | 原版群友 | "喵"是每轮的底线（不是点缀），傲娇只做调味、落点是"给" |

新增内置卡的方式：在 `roles/` 下新增 markdown 正文，再到 `src/personas.js` 登记。
正文只写在该目录，用真实工具名，不引用旧架构专属指令。
`test/personas.test.mjs` 会检查登记一致性与工具名有效性。

## 选择与保存

1. 打开控制台「设置 -> 人设」。
2. 在人设卡库里点一张卡（正文会填进草稿），确认「交流策略」，按需调整角色正文与管理员附加规则。
3. 点页面底部常驻的「保存设置」。

选择模板只填入草稿，保存后才生效。机器人名字、群内展示名与参与度保留现有设置，
不因选择模板被重置。角色修改适用于之后新建的模型请求，不撤回在途请求或已发送的消息。

「＋ 新建自定义卡」可以当前草稿为基础创建自定义副本，正文、附加规则与交流策略随副本一起保存。

正文按小节展示，每节右上角有「编辑」（只改这一节，小节标题不动）与「恢复本节」（只把这一节
还原成卡文件里的写法）；整篇改乱了用详情头的「恢复整张卡」。想直接改整段 markdown 就点
「编辑全文」。逐节编辑只改草稿，仍需点底部「保存设置」才生效。
更新代码不会强制切换现有实例已保存的角色；改用其它模板并保存即可切换。

**名字与人格是两回事**：名字只是群里的称呼，人格、口吻与身份由角色卡决定，
两者不必一致（名字叫「小鲸鱼」而卡是猫娘，是允许的）。提示词的开场白明确写了这条分工
（「你在群里的名字是……；你是个什么样的人、说话什么调子，看下面的【角色设定】」），五张内置卡里也各有一条
"名字跟卡不搭时怎么答"的规则：被问到就把名字和卡名都说出来（"名字是小鲸鱼，人设是猫娘"），
不改设定、不编另一个身份、也不因为名字不搭就把招牌藏起来。

**三个名字字段的优先级**（`resolveSelfName`，聊天、说说、空间互动、好友评估、看图判断统一口径）：

1. **群内展示名**（`persona.selfNickname`）：填了就代表"群友看到的名字"，优先级最高；留空则跳过。
2. **账号昵称**（QQ 侧昵称，运行时从协议端读取）：群内展示名留空时用它 —— 这才是群里实际显示的名字。
3. **机器人名字**（`persona.botName`）：前两者都没有时的兜底，也是控制台与文档里的项目标识。

所以想让名字彻底统一：在 QQ 侧把昵称/群名片改成想要的名字，再把「设置 -> 人设」里的
**机器人名字**与**群内展示名**都填成同一个；或者把"群内展示名"留空，让它自动跟随 QQ 昵称。
改名字会变更人设哈希，说说与空间互动的既有内容会被视为"人设已变"而重新生成。

控制台里看到的是**当前生效的那份正文**（`config.json` 的 `persona.roleText`），
但内置卡的正文源头永远是 `roles/*.md`：

- 在控制台**选中一张内置卡**时，会同时记下它的人设 id（`persona.templateId`）。只要还绑着，
  重启服务（以及任何一次配置保存）都会按卡文件刷新实例里的正文 ——
  **改了 `roles/` 下的卡，重启即生效，不用再去控制台重选一次**。
- 在控制台**手写或改动正文**（或选择自定义卡）会自动解绑（`templateId` 清空），
  之后卡文件再改也不会覆盖你写的正文；想重新跟随卡文件，去控制台重选一次那张卡。
- 老配置没有 `persona.templateId` 字段时按"未绑定"处理、保留现有正文，
  不会因为升级被换回默认卡（回归用例见 `test/persona-template-sync.test.mjs`）。
- 直接手改 `config.json`（不走控制台）时注意：新装的实例默认绑着默认卡
  （`templateId: "xiaojingyu"`），只改 `persona.roleText` 会在下次启动被卡文件刷回去。
  想固定自己写的正文，就把 `templateId` 一起清成空串。

## 语气档位

- `legacy`（界面显示「原版群友」）：缺少字段时的默认档；输出保持旧版兼容。
- `grounded`（界面显示「自然可靠」）：允许技术说明所需的长度、编号与代码，取消通用规则中
  鼓励装傻乱答、固定短句上限与按轮数凑表情的要求。

非法档位值在配置保存与创建模板接口中被拒绝，不写入配置。管理端
`GET /api/persona-templates` 返回每个模板的 `behaviorProfile`；创建自定义模板可传同名字段，
旧客户端省略该字段时仍得到 `legacy`。

## 生效范围

角色正文通过现有配置同时进入群聊、私聊、每日动态、动态互动与好友评估。`grounded` 只替换
普通聊天的风格策略，其它场景仍使用各自的工具协议，不额外注入群聊流程。安全边界、会话绑定、
观察模式、白名单、时间控制与未知发送结果保护继续有效。

生命周期会因系统提示变化在下一次请求重新建立上下文前缀，已有检查点仍按原机制处理。

## 技术内容发送

自然可靠档使用 Markdown 代码围栏或行内反引号标明代码。发送层在处理普通文本格式前保护代码，
只去掉围栏，保留缩进、换行与 `*`、`>`、`|`、下划线等内容；整段代码尽量放在同一个气泡，
超长内容仍遵循 QQ 消息长度限制。

代码保护由当前 Agent Session 的策略快照决定，不接受群友自定义工具权限；运行途中管理员切换
人设，本轮仍保持原本的发送约定。旧版发送格式不变。

模型没有执行代码、读取宿主机文件或操作引擎的工具。代码只是未经运行的建议，不能声称完成
构建或测试；会话交接也不是定时任务。

## 第二人设（按群召唤）

除了上面那套"全局人设"，还可以配一个**第二人设**：群友在某个群里点名召唤时，这个群临时换一套
人设与模型；闲置超时后自动交还默认人设。默认关闭，配置在控制台「设置 → 第二人设」。

- **开关与就绪**：`personaSwitch.enabled` 打开只是前提，还必须同时填了**模型**与**角色设定正文**
  才会生效（控制台那一页会直接告诉你还差哪一项）。
- **模型怎么选**：点「选择模型」从现有模型目录里挑（也能直接粘 id）。注意这里**只换模型名、不换渠道** ——
  机器人仍用 `api.provider` 那条渠道，所以模型必须属于当前渠道：控制台会对照目录给出
  「当前渠道有它 / 渠道不匹配（属于别的提供商，请求仍会打到当前渠道，多半 404）/ 目录里没有」三种提示。
  中转站把 Gemini 与 Claude 都挂在一个地址下时，直接挑那个地址的 claude 即可。
- **触发**：光提到名字不算。要么 `@`/引用机器人，要么话里带呼叫动词
  （默认：呼叫 / 叫 / 喊 / 出来 / 换 / 值班 / 接管 / 救命 / 在吗 / 来），再带关键词
  （默认：claude、克劳德；叫回默认人设的词默认：gemi、哈基米）。同一句里两边都提到时按"拿不准"处理，不切。
- **计时**：从第二人设**最后一次真正发出消息**起算 `idleMinutes`（默认 30 分钟），期间每发一次续期；
  另有 `cooldownSeconds`（默认 60 秒）防来回横跳。
- **交还**：闲置到期自动回默认人设；管理员可在「设置 → 第二人设 → 正在值班的群」里点
  「叫回默认人设」立即收回；模型自己输出控制标签 `[SWITCH_TO_GEMINI]` 也会立刻交还
  （这个标签在发送前被剥掉，不会出现在群里）。
- **群名片跟着换**（`personaSwitch.renameGroupCard`，默认开）：切到这个群时把它自己的群名片改成第二人设的名字
  （`altPersona.botName`，没填就用 `altName`，默认「Claude」）；交还（闲置到期 / 管理员叫回 / 模型自己交还）时
  改回**原来那张名片** —— 第一次切走前先用 `get_group_member_info` 记下当时的 card，记不到就退回「机器人名字」
  （`persona.botName`，例如「Gemi本咪」）。只影响群聊（私聊没有群名片）；没有群名片权限的群会失败并退避 10 分钟
  再试，不刷日志、不影响聊天。判断是纯函数 `planGroupCard`，「没改过名片的会话永远不碰」这条就在里面。
- **头像也能换**（`personaSwitch.switchAvatar` + `altAvatar`/`homeAvatar`，图片留空＝不动）：头像是**账号级**的，
  所有群和私聊共用一张，所以做不到"这个群 Claude、那个群 Gemi"；规则是**有任意会话在第二人设值班就用
  `altAvatar`，全部交还就换回 `homeAvatar`**。图片填宿主机绝对路径、URL 或 base64（走 SnowLuma/NapCat 的
  `set_qq_avatar` 扩展动作，不是 OneBot 11 标准动作）。切换有节流（20 秒内最多一次）与失败退避（10 分钟），
  当前状态记在 `data/persona-avatar.json`，重启不会重复上传同一张。
  注意头像生效有几秒延迟，且不改变已发消息的头像 —— 群友看到的是"下一条消息换了张脸"。
- **召唤前先探活**（`personaSwitch.probeOnSwitch`，默认开）：召唤时用第二人设的模型打一个
  `max_tokens=1` 的极小请求。额度用完 / 欠费 / 401·402·403 / 模型不存在 → **不切**，
  由当前人设说一句"他暂时有事，我先顶着"；429 限流、5xx、超时**照常切**（一次抖动不该让它"今天不上班"）。
  成功缓存 30 分钟、失败缓存 5 分钟，同一个群反复喊不会反复探。
- **站岗中途挂了就临时交还**：第二人设的调用遇到额度/鉴权类硬失败时，立刻交还默认人设
  （名片、头像跟着回），这一批消息回到队列由默认人设重答。第二人设的调用显式 `noFallback`
  —— 宁可换个人答，也不要"Claude 的词配别家的脑子"。
- **记忆是分开的**：第二人设用自己的印象库 `data/memory-alt`（与默认的 `data/memory` 同结构），
  从空白开始，看不到默认人设记过的群印象，反之亦然。会话交接、自动整理、控制台的记忆页都按
  会话当前的人设档走同一套路由，所以**在记忆页里看到、改到的就是模型真正读到的那一份**
  （列表与详情都会标出「第二人设」）。删除"全部人物记忆"对两个库都生效。
- **身份边界**：切到第二人设后 24 小时内，提示词会在【过去状态】段头提醒"角色设定刚换过，旧记录的
  口癖与自称不作数"（复用切换时刻 `chatProfile.since`，不另存时间戳）。默认人设下这句不会出现，
  提示词与升级前逐字一致。
- **展示名**：`altPersona.botName` 只影响群内称呼，其余字段（`name`/`model`/`roleText`…）是历史形状，
  实际生效的是 `personaSwitch.alt*`，控制台也只写这一份。

真实群验证建议先只开一个群，观察呼叫识别与 30 分钟交还是否符合预期。

## 验证

```bash
node --test test/personas.test.mjs test/persona-behavior.test.mjs test/persona-chat-switch.test.mjs
node --test test/memory-persona-isolation.test.mjs test/persona-switch-api.test.mjs
node test/test-prompt.mjs
node test/render-test.mjs
```

用例覆盖角色源与登记一致性、默认兼容、场景注入、配置持久化与非法值、代码格式、
Agent 到出站队列的完整发送，以及管理 API 的选择、自定义与回退。这些验证证明配置与运行链路
正确，不代表模型在真实群聊中的长期表现。
