# 功能管理与后台任务

主导航“功能”现在先进入“功能总览”：可搜索名称/用途，按启用、关闭、异常或待核对筛选，
从卡片进入已有配置页。每晚汇报的内容设置、JM 等现有功能保持原有业务逻辑和配置。
公开清单位于 `ui/core/feature-catalog.js`，它是无依赖的公共元数据，后端与前端共用；
禁止在清单中加入凭据、运行配置或执行钩子。开关仍在各自配置页保存，不新增第二套配置。

`src/core/background-tasks.js` 统一注册、幂等启动、按功能配置变更同步、停止及安全状态摘要。
`src/core/app-background-tasks.js` 连接现有调度器，集中管理消息恢复、提醒派发、会话定时唤醒、
每日动态、动态互动、群日报、群游戏推进、主动发言、主动私信、更新通知与每晚汇报。

统一层协调生命周期；具体时刻、退避、白名单、活跃时段、任务持久化和发送幂等仍由模块负责。
它不新增一套轮询，也不重排历史任务。消息恢复、群游戏推进等基础监听可常驻，实际业务开关
继续由模块判断；更新通知检查常驻不代表自动更新开启。暂停/观察状态下，各任务沿用已有规则。
启动或配置同步失败只隔离该调度器并标记异常，尝试清理部分启动的资源；
状态刷新和无关配置保存不会自动重试失败启动，更不会重发结果未知的外部写入。
关闭应用时统一停止全部注册调度器，单个停止失败不妨碍其他清理。
群日报取消时会中止在途模型请求，发送前再次检查取消信号；关闭应用还会等待其收尾。
每日动态、动态互动等仍按各自的取消与未知写入保护规则收尾，不宣称能撤回已经发出的请求。

认证接口 `GET /api/features` 只返回公共清单、开关及标量运行摘要，不返回配置原文、聊天正文、
API Key、任务载荷或原始异常。等待调度并不代表业务成功，未知发送只标为待核对。
状态时间是本次进程内观测，不替代模块自己的持久化任务记录。

后台卡片展示最近执行、最近成功、最近失败时间与脱敏原因，以及下次检查/调度时间。
恢复巡检、提醒、会话唤醒、游戏推进、主动发言/私信、更新通知记录的是“检查完成”，
即使本轮没有需要执行的业务也可能正常完成；不能据此推断QQ已发送。
每日动态、群日报和每晚汇报仅以已确认发送记录显示“发送成功”；动态互动以完整done记录表示检查完成。
部分失败与结果未知不会被当作成功。持久化模块从保留记录摘要，其他检查及群日报的时间在重启后重新积累。
历史失败在恢复后继续显示时间与原因，当前异常标记按最近结果判断；停用/停止后不显示旧的未来计划。
无记录明确显示“尚无记录”，没有模块提供的计划显示“暂未提供时间”。
观测只在既有回调中记录固定数量标量，不添加定时器、不保存错误对象或原文，不改变重试、发送和调度规则。

独立 systemd 的备份、健康巡检、进程保护、审计清理、自动更新执行和东京恢复 worker
保留原来的运维边界，总览给出说明，不伪装成由应用进程接管。
