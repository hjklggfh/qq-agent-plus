# 每晚用量与服务器报告

在「功能 → 每晚汇报」启用，默认时间为北京时间 23:00，接收人为
`admin.ownerUin`。已有安装默认关闭，不会因升级自动开始发私聊；保存立即生效。
配置为 `dailyReport: { enabled: true, time: "23:00" }`，启用必须配置全局管理员。

“发送内容”可分别勾选 Token 用量、今日费用、Agent 与 QQ 状态、运行时长、CPU 负载、
内存与 Swap、磁盘空间、I/O 压力，至少保留一项。旧配置默认全部勾选，保留原有开关和时间。
字段为 `dailyReport.content` 中的 `tokens/cost/status/uptime/cpu/memory/disk/io` 布尔值；
部分修改保留其他选项。“预览发送内容”按未保存的勾选和当前真实数据生成，只在网页显示，
不保存设置、不预留发送记录、不向 QQ 发送。切换页面或刷新状态保留未保存的编辑草稿。

每 30 秒检查一次；每天从北京时间零点统计到报告生成时刻，不包含当晚剩余时间。
费用复用控制台会话留档与当前价格配置，分别显示配置价格、估算、未定价调用、包月固定支出、
本地不按量调用。缓存 Token 已包含在输入中，不重复加总。包月不分摊成每日支出；
不包含服务器租金、搜图等第三方非模型服务费用，不宣称是供应商最终账单。
会话留档尚未刷盘的调用可能暂未计入；已被清理或未记录的用量无法重建。

服务器指标在报告生成时只读采集 Agent 所在主机，杭州部署后即为杭州主机：
主机和进程运行时长、OneBot 连接、CPU 核数与 1/5/15 分钟负载、可用内存、进程 RSS、
swap 已用、数据目录所在文件系统总量/可用空间、Linux I/O PSI full avg60。
负载不是 CPU 使用率，单个快照也不能证明卡顿根因。指标不可读取时明确标为不可用。
不访问东京、不读取聊天正文、不调用模型或云端 API，不执行重启或恢复。

这是管理通知，不受普通聊天活跃时段限制；观察模式、暂停、未设置管理员、
OneBot 未连接时不发送。当天到点后条件恢复可以补发，跨日不补历史报告。
停用中止尚未写出的报告并保留记录；已经发给 QQ 的请求无法撤回。

`data/daily-report.json` 在发送前原子写入并 fsync，每日最多尝试一次。
QQ 请求同时记入宿主 outbox。重启、超时、部分送达或崩溃后不会自动重发；
状态 `unknown` 表示需要人工核对，可能已经发送，也可能尚未发送。
宁可漏一日报告，也不重复骚扰管理员。单进程运行，沿用 systemd 用户服务部署约束。
启动时发现损坏状态文件会停止该功能的发送，不能将其当作“今天还没发送”。

只读状态接口：`GET /api/daily-report`（沿用控制台鉴权）。
只读预览接口：`POST /api/daily-report/preview`，请求体为本功能设置补丁，沿用相同鉴权。
关闭方式：取消启用并保存；回滚代码时保留状态文件，不删除业务数据。

本地验证用模拟 QQ 发送，不主动向管理员发测试消息。
