# JM 禁漫下载

JM 是宿主内置的单功能模块，不属于可安装插件，也不会出现在“插件”页面或能力审批列表中。

## 设置

打开“设置 → JM 禁漫下载”，可直接开启或关闭并配置输出格式、并发、超时、PDF 处理、上传方式、群文件保留、触发白名单和 Python 路径。配置保存在顶层 `config.jm`，默认关闭。

旧版本写在 `plugins.settings.jm-suomingor` 的配置会在启动时自动迁移到 `jm`，历史数据继续使用：

```text
<dataDir>/plugin-state/jm-suomingor/
```

## 能力

JM 工具由宿主内置工具表注册：`jm_search`、`jm_download_album`、`jm_control`、`jm_group_toggle`、`jm_task_status`、`jm_today_list`、`jm_daily_updates`、`jm_library` 和 `jm_storage`。下载、PDF/图片处理、群文件上传和日更功能继续复用原 skill 实现。

私聊或已开启 JM 的白名单群均可发送「JM搜索 关键词」；群聊可直接发，也可 @机器人。搜索结果以每页五部的合并转发卡片发送，在原会话里回复「下一页」「上一页」或作品序号。翻页和序号只对应发起搜索的群成员，不会让同群其他人的消息触发下载。

群聊完整卡片保留名称、标签、作者、简介和封面，省去外站直链。部分封面卡片可能被 QQ 群消息链路吞掉，即使 OneBot 返回了消息 ID。群聊发送后会核对群历史；确认未出现时，尝试保留所有文字详情的无封面卡片。若详情版也未进入群历史，再补发只含序号和 JM 编号的六条简版卡片。三种版本都可用序号选作品。私聊仍显示封面和外站直链。

封面在宿主完整解码并转换为标准 RGB JPEG，最大 512×768、256 KiB；每张封面最多尝试两个来源，失败时仅该作品显示“封面暂不可用”，不再把裸外站 URL 交给协议端。最终编号简版同样核对群历史；序号为 0 的缓存消息不算确认送达。群历史查询不可用时停止自动降级，返回待核对状态，避免把未知送达当成失败重发。图片规范化是兼容性加固，不代表已证明 QQ 未接受带图卡片的根因。

工具只能操作当前会话；群文件和私聊文件操作由宿主内部的受限 OneBot 门面执行。

群白名单由群内指令管理：只有目标群群主或机主 QQ `2118530760` 可以执行 `开启JM`、`关闭JM`、`JM群列表` 和 `JM所有群开放`。普通管理员不能修改 JM 群白名单；白名单群内的普通群友可以正常使用 JM。历史配置中的 `allowIds` 不会再限制已开启白名单群内的下载请求。

PDF 合成会逐页解码、还原并写入临时 PDF，同一进程只运行一个 PDF 任务，避免多本同时合成耗尽服务器内存。单页超过 2400 万像素时会跳过该页并在结果中报告；全部页面失败时不保留不完整的 PDF。合成成功后才会将临时 PDF 替换为正式文件。

## 下载并发与 CDN 策略

下载并发范围为 1～48，默认仍为 4。设置保存后新任务读取最新值，已经开始的任务保留启动时的并发和 CDN 策略。不要依据某一轮网络测速直接把所有实例默认值提高到 48。

- `jm.cdnStrategy: "adaptive"`（默认）：以杭州已验证的 `cdn-msp.jmapiproxy2.cc` 为初始优先节点，在两个主节点间按实际成功率、响应延迟和完整传输耗时选择；每 16 张图片最多借一张正常请求采样尚未使用的主节点。其余原有 CDN 保留顺序兜底。
- `jm.cdnStrategy: "fixed"`：回到保留杭州调整的固定顺序与带／不带 `v` 参数兼容请求，不启动提前备用请求。网页的“图片 CDN 策略”可直接选择该模式。
- 慢请求从 3 秒阈值开始，已有观测时提高至传输耗时的约两倍（最多单次超时的 65%），避免高并发下把正常延迟都当作异常。每张图最多有一个提前备用请求；全进程额外并发最多 4，低并发任务更少，每任务累计额外请求不超过已开始图片数的 10% 向上取整。成功后取消冗余请求，失败仍有界尝试保留的 CDN／URL 兼容候选。
- 使用现有 Node fetch 的 Keep-Alive 池，不更改全局 dispatcher；代理继续复用任务自己的 ProxyAgent，任务结束后关闭。宿主图片响应透传为流，只有 API 等既有请求保留缓冲适配。

图片流式写入同目录随机 `.part` 文件，限制单图 32 MiB／2400 万像素，校验 HTTP 状态、内容类型、长度及编解码器完整压缩流解析。验证使用丢弃输出的缩略解码，正式图片始终按收到的原始字节保存，不压缩或替换为缩略图。全进程串行验证，避免随着 48 并发同时生成几十份整页像素缓冲；验证完成后才原子替换正式文件。已有坏缓存会补下，正常缓存继续复用。取消任务中止在途请求、等待清理临时文件，再执行用户指定的删除，避免晚到请求重新生成目录。

各 CDN，甚至同域名不同时间，可能提供不同编码版本；完整下载成功不等于与另一轮样本逐字节／逐像素一致。对要求固定来源的任务可使用 `fixed`。超时与换节点不改变竖切还原参数、文件顺序、PDF 合成、上传或已有保留策略。

## 性能日志与对照

`journalctl --user -u qq-agent-linux.service -o cat | rg '\[jm-(download|performance)\]'` 可检索两类 JSON：

- `[jm-download]`：配置与实际图片工作并发、图片数、成功／失败／缓存数、成功下载原始字节、已读取的响应体字节（含失败／冗余请求已读部分，并非网卡总流量）、图片阶段墙钟时间与 MiB/s、各 CDN 的使用次数／成功／失败／首包和传输 EWMA、切换／超时／重试／提前备用次数，以及最慢 5 张图片。
- `[jm-performance]`：下载、PDF 管线（包括排队）、实际竖切还原、PDF 写入、QQ 上传与完整任务耗时。缓存命中的 PDF 不虚报合成时间。PDF 管线包含其子阶段，数值不能相加当作总耗时；下载吞吐也不是完整任务吞吐。日志不记录鉴权、代理凭据或图片内容。

隔离基准脚本为 [benchmark-jm-download.mjs](../scripts/benchmark-jm-download.mjs)，默认只启动回环故障 CDN。显式传 `--live --manifest=/path/manifest.json --baseline=/path/old-engine.js` 才访问外部 CDN；清单必须含固定章节 ID、96 个文件名及可选 CDN 列表。16／24／32／48 档逐轮执行，每轮最多 144 次网络请求、90 秒，轮间等待 2 秒，输出成功率、吞吐、p95／最慢 5 张、流量、RSS 与内容差异，不能直接当作含下载／还原／PDF／QQ 上传的全任务提速结论。
