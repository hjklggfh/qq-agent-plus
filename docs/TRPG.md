# 轻量叙事跑团

跑团是宿主内置功能，入口为控制台左侧「跑团」。默认关闭，适合单人或最多6人的小群，不需要安装市场插件、额外模型或代理。

**新：诡秘战术长期战役** 已支持22途径自建、序列9—5成长、按QQ隔离的编号菜单和程序结算的方格战斗。发送 `/跑团 开团` 使用新内置战役，再由每人 `/跑团 建角`。完整玩法、资源规则、迁移与回退见 [战术战役说明](TRPG-TACTICAL.md)。本文其余卡片示例主要用于兼容的原轻量叙事模式。

**退出语义更新**：“退出游戏”保存暂停，可用“继续跑团”恢复。正式结束战术战役需团主发送“结束战役”后 `/跑团 确认结束`。原叙事团仍可用 `/跑团 结束` 正式结束。

## 设置与卡片

在跑团页面开启功能，填写群聊白名单（群号）、私聊白名单（QQ号）及人数上限，再保存。每行一个号码，也支持逗号或空白分隔。配置写入 `config.trpg`，立即生效；全局会话授权、运行模式、暂停、时段与模型预算仍然有效。

跑团白名单独立于全局白名单：`allowedGroups`、`allowedPrivate` 分别保存群号与QQ号字符串数组。名单为空或旧配置缺少名单时，禁止对应类型会话开团；升级后需要先在工作台添加允许的号码。群白名单允许该群成员开团，不要求每名群成员另加私聊名单。移出名单会立即中止正在生成的跑团回复并停止接管，存档保留；重新加入名单后可继续原存档。未在名单中的已有团仍允许查询状态、暂停或结束，不能开始、继续或推进剧情。

- 世界观：名称、背景、开场、世界规则与叙事风格。
- 角色卡：名称、描述、初始生命值、属性修正值、初始物品。
- 网页新建的卡为公共模板；聊天创建的卡仅在当前会话可见，角色仅创建者可选。控制台管理员可以管理全部卡片。
- 支持本页JSON卡片导入导出及TXT/Markdown设定导入。JSON角色卡可读取酒馆v2的基础描述、性格和场景，但不执行脚本，不支持PNG卡，也不兼容完整酒馆提示词系统。
- 导入先填入编辑器，确认后保存；刷新存档不会重画编辑器或清空草稿。
- 开团时复制世界与角色快照，后续修改/删除模板不会改变已经开出的团。

### 如何添加

完整的字段要求、内容提纲、可导入模板及可复制给AI的生成提示词，见 [角色卡与世界观编写指南](TRPG-CARD-GUIDE.md)。

最方便的方式是打开网页「跑团」：在世界观编辑器和角色卡编辑器直接填写并保存，不要求整张卡写成JSON。角色的「属性修正值」单独使用JSON对象，例如 `{"力量":0,"敏捷":1,"感知":2,"交涉":1}`；「初始物品」每行一项。保存后复制列表中的ID，用于QQ开团或加入。

这里的角色卡是玩家使用的角色。主持人扮演的NPC可以写在世界观背景中，注明姓名、身份、性格、目标和关系；目前没有独立NPC卡库。世界观可按「时代/地点/势力/关键NPC/能力边界/主要冲突」组织，角色描述可按「身份/外貌/性格/经历/目标/能力/弱点」组织，也可以自由写段落。

如果想在文件里维护，复制以下两个可直接导入的示例：

- [角色卡 character.json](examples/trpg/character.json)
- [世界观 world.json](examples/trpg/world.json)

修改文件里的 `asset` 内容，保留 `kind`：角色为 `characters`，世界为 `worlds`。在相应编辑器点击「导入 JSON / TXT」，检查后点击保存。不要手动填写ID，保存时会自动生成。也支持不带外层包装、只有 `asset` 内容的JSON对象。

| 字段 | 含义与限制 |
| --- | --- |
| `name` | 两类卡均必填，1—60字 |
| `description` | 两类卡均必填，1—12000字的自由文本 |
| `opening` | 世界观可选，开场剧情，最多4000字 |
| `rules` | 世界观可选，规则、风格与边界，最多4000字 |
| `characterCreation` | 通用叙事世界可选的建角配置，包含公开说明、职业、属性方案及初始物品，见下节 |
| `hp` | 角色可选，初始生命值，整数1—1000，默认10 |
| `attributes` | 角色可选，最多12个自定义属性，每个修正值为-5至10的整数；填的是修正值，不是百分制能力值 |
| `inventory` | 角色可选，物品名称字符串数组，最多30项，每项最多120字 |

纯TXT/Markdown导入时，文件名作为名称，正文作为描述；生命值、属性、开场等结构化字段需要在网页补充。QQ快速建卡也只写名称和描述，其余使用默认值，详细配置建议用网页。

## 按世界建角

先 `/跑团 开团 世界ID` 选择世界，再由每人 `/跑团 建角`。省略世界ID仍会使用内置诡秘战役，不会自动选中最后导入的世界。

- 通用轻量叙事世界：输入职业/身份、姓名、背景，选择属性方案后确认，自动加入当前待开始战役。没有诡秘途径、序列、灵性或消化，默认HP10、通用四属性方案、空背包。旧世界不必重新导入即可使用。
- 诡秘战术世界（`ruleset: "lotm-tactical-v1"`）：保留22途径、序列9和既有资源规则。网页规则模式需明确选择；它是专门的诡秘引擎，不适合把现代或其他题材世界直接改为此模式。
- 建角草稿绑定会话、QQ和具体战役；换团、开始或正式结束会清理对应会话草稿。升级前未绑定世界的草稿会重新提示，不把当前回复误当成新世界答案。已创建角色及存档保留；重复建角不会替换已入团人物。
- 普通世界仅在待开始阶段建角；诡秘团也可在非战斗暂停期间建角。没有开团时会提示先选择世界。

网页世界编辑器可填写「建角说明」和「可选职业／身份」。不填职业时由玩家自由输入；填写后按编号选择，可分页，也可选择9自填其他身份。世界背景可能含主持真相，不直接展示给建角玩家；只有世界名称、公开开场和明确配置的建角说明用于引导。职业是否符合叙事、背景技能能产生哪些后果仍由主持判断，不是自动生成一套新规则引擎。

高级配置可在网页折叠区填写，也可导入 `asset.characterCreation`。完整示例：[现代求生世界与建角配置](examples/trpg/narrative-world-with-creation.json)。

| 建角字段 | 限制与含义 |
| --- | --- |
| `prompt` | 公开建角说明，最多1200字，勿填案件谜底 |
| `roles` | 最多30个不重复的职业/身份名称，每项1—60字；空数组或省略为自由输入 |
| `backgroundPrompt` | 填写背景时的公开问题，最多1200字 |
| `hp` | 初始HP，整数1—1000，默认10 |
| `inventory` | 初始物品，最多30项、每项1—120字，默认空；同名重复条目代表多个单位 |
| `attributePresets` | 1—6个 `{ "name": "方案名", "attributes": { "属性名": 修正值 } }`；方案名1—40字，1—12个不重复属性，名称1—20字，修正为-5至10的整数；省略使用通用方案 |

这些字段仅用于通用叙事模式，诡秘模式不接受覆盖建角资源的自定义配置。配置经服务端校验，网页导入、编辑、保存和导出均保留；开团后按世界快照执行，修改模板只影响新团。建角本身不调用模型、不消耗聊天Token。

## QQ 指令

必须在已授权且可运行的群/私聊内发送，指令不需要额外@。除「行动」外均由代码处理，不调用聊天模型。

```text
/跑团 列表
/跑团 世界 雾港 | 一座永远被浓雾包围的港城，风格为奇幻调查
/跑团 角色 阿澜 | 一位沉默的调查员，擅长观察，携带一本旧笔记
/跑团 开团 mist-harbor
/跑团 加入 traveler
/跑团 开始
我举起提灯，观察码头上的脚印
/跑团 掷骰 1d20+2
/跑团 状态
/跑团 暂停
/跑团 继续
退出游戏
```

`mist-harbor`（雾港来信）和 `traveler`（旅人）为示例模板。自建卡的ID在保存回执和网页列表中显示。

每个会话同时只能有一团。开团者为团主，至少一人加入后才能开始；只有团主能开始、暂停、继续或结束。角色选择在开场前完成，开场后不替换人物。进入「游戏中」后，在册玩家的普通消息自动成为行动，无需 `/跑团` 前缀或@，直到暂停、结束、关闭功能或移出白名单；旁观者消息不唤醒模型或推进剧情。游戏行动优先于JM、B站等自动处理。单条行动最多2000字，图片需附文字描述。

保留 `/跑团 行动 内容` 的旧用法，以及 `/跑团 状态、暂停、继续、结束` 指令。已有团时还可直接发送「跑团状态」「暂停跑团」「继续跑团」「退出游戏」（「退出跑团」同样暂停）；仅团主可暂停整团，也支持 `/跑团 退出`。退出后该窗口恢复普通聊天，可继续原战役；正式归档按本文顶部说明操作。

暂停保留进度，可继续同一团；结束后存档只读，下一团可使用相同或新的卡片。当前提供存档JSON导出、暂停/继续和已结束存档删除，不提供存档JSON导入、分支回滚或替换已有玩家角色。原叙事团不支持中途加入，新战术团可在非战斗暂停期间接纳新玩家。

## 规则与主持

**窗口级裁判／旁白模式**：当本会话的团为「游戏中」时，所有模型回复（包括规则答疑与普通消息）使用独立的中性主持系统提示词，不加载原聊天角色正文、管理员附加人设风格、亲疏印象或普通聊天交接。保留安全规则和工具发送协议，并抑制表情包、拍一拍及QQ表情。历史消息仅作事实参考，不模仿其中口癖和情绪。NPC可以按剧情表达情绪，但需要标明身份，不能混成旁白对玩家的好恶。

该模式只作用于本团对应的群聊或私聊；其他窗口不受影响。暂停、结束或关闭跑团后，后续模型调用恢复正常聊天人设。它是提示词及工具范围的约束，不是逐句判断情感的确定性过滤器，实际措辞仍受所选模型影响。

这是轻量叙事规则，不是完整的COC或DND实现。默认检定使用 `1d20 + 属性修正`，通常难度12，其他难度由主持结合世界规则和情况说明。属性修正为-5至10；HP表示生命/行动能力，降至0后的剧情由主持和玩家共同决定。

程序负责骰子、当前HP、背包、状态与持久化；模型负责环境、NPC、后果与故事，不能替玩家做重大选择。模型应先说明风险再检定；结果判读属于叙事主持，不是完整战斗规则引擎。手动掷骰会保留明细，主持可在下一次行动时参考。

模型只在本团在册玩家的行动中获得 `trpg_state`、`trpg_roll`、`trpg_update` 与文本发送/收尾工具，不获得其他游戏外工具。每轮先成功保存地点、累计剧情摘要及必要的玩家状态，再允许发送叙述；当前版本没有单独的主持秘密库，设定和存档应视为本团公开信息。

骰点来自Node加密随机数。模型同一行动中使用相同 `checkId` 和相同参数重试，会返回原结果而不再掷骰；同ID改参数被拒绝。最近120项工具结果保留用于重试去重。状态更新使用版本校验，冲突需重读，不盲目覆盖。叙述发送沿用宿主outbox与未知结果不自动重发机制。

## 数据与成本

数据保存在 `<dataDir>/trpg/state.json`，卡片、存档、最近事件与去重结果原子写入；部署时保留整个数据目录即可。关闭功能不会删除数据，首次未启用且未保存任何卡片时不创建数据文件。损坏文件拒绝继续写入，先从备份恢复，不以空存档覆盖。

每类卡片最多200张，总存档最多100个，文件最多16MiB。每团保留最近60项事件、累计剧情摘要和当前状态；它不是无限全文日志，完整模型叙述仍在宿主聊天/会话存档中。达到容量时先导出旧团，再结束并删除旧存档。

行动叙述使用现有聊天模型，照常消耗Token并受原有预算、时限和轮数限制。卡片文本会随游戏上下文发送给所配置的模型服务。无需额外搜索或视觉API。

运行中关闭、暂停或结束本团会中止正在生成的跑团回复。已经保存的剧情不会回滚，已经发出的消息也不会撤回；重新开启后查看状态，再由玩家提交下一次行动。
