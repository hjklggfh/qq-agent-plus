# QQ Agent Plus v8.1.2

本次更新集中完善 PID 多页取图、PDF 发送与下载速度，并修复普通世界建角误用诡秘规则的问题，加入按世界自由分配属性。GitHub 首页 README 已按当前功能重新整理。

## PID：多页 PDF 与简洁回执

- 发送 `PID 作品号 PDF`，把可取得的图片按原始页码顺序打包；支持 `PID 作品号 21-40 PDF` 指定范围，也可在设置中选择默认 PDF。
- 群聊上传为群文件，私聊发送文件。复用 JM 的 Python 3 + Pillow 逐页写入器，共用串行 PDF 队列，降低小内存机器的合成峰值。
- 单作品正常完成只发送开始提示、PDF 文件、完成总结共3条，不再每隔几页发进度文本，也不在总结中枚举全部页码；阶段状态、缺页明细保留在任务记录。
- 未取得图片时显示接口 HTTP 状态、超时或大小限制等具体原因，避免统一归因于分级或作品被删除。

PDF 仍受权限、分级、页数、大小及超时限制。图片可能压缩；只有已知总页数且全部取得才标为完整作品，其他情况明确提示“部分／完整性未确认”。

## PID：下载与缓存

- 复用原有 pixiv.re / i.pixiv.re 图源，支持从公开详情或可信响应头解析真实图片路径，对指定瞬时图片 GET 错误有限重试。
- 可选独立东京链路：代理官方详情请求，也可在东京下载、压缩 CDN 图片后返回。与以图搜图的服务、隧道和凭据独立，不要求所有实例配置东京。
- 已有可靠页地址时有限并发下载，默认4个工人、最多预取并发数两倍的窗口；慢页不阻塞其他空闲工人，最终 PDF 保持原顺序。
- 有界复用 SSH 批次与 CDN HTTPS 连接，减少逐页建连开销；东京串行图片解码，限制图片大小、像素和进程内存。
- 默认缓存已验证图片与完整 PDF：24小时、总量512 MiB，启动、任务、写入及每30分钟检查清理，超量淘汰较旧文件。部分作品只复用成功图片，不把部分 PDF 当作全本。
- 命中缓存前重新检查会话权限和分级，校验文件摘要；来源、尺寸、压缩或凭据等变化会隔离旧缓存。发送结果不明确时仍不自动重复上传。

实际速度取决于作品页数、图源、网络与 QQ 上传；重复请求命中缓存与首次下载的耗时应分别看待。

## 跑团：按世界建角与自由加点

- 普通叙事世界按本世界的身份、姓名、背景、属性与初始物品引导建角，不再套用诡秘途径。诡秘战术模式保留原有22途径规则。
- 网页世界编辑器可设置自由加点的属性名、总点数和单项上下限，也可选固定属性方案；JSON 导入导出保留配置。
- 玩家可按菜单顺序输入 `4 3 3`，或使用 `力量4 敏捷3 防御3` 等格式。程序检查名称、整数、范围与合计，分配后由本人确认，不消耗建角模型 Token。
- 团主可在待开始或已暂停的普通战役中发送 `/跑团 设置加点 力量 敏捷 防御 | 10`；玩家本人 `/跑团 重新加点`，保留姓名、背景、当前HP、背包与剧情。
- 建角草稿绑定具体战役，切换世界、开始或结束时清理相应草稿；已有角色与存档保留。未完成加点时阻止恢复，避免新旧规则混用。

省略世界ID的 `/跑团 开团` 仍使用内置诡秘战役；自建世界需发送 `/跑团 开团 世界ID`。自由加点保存实际属性值，不会自动新增战斗公式或技能系统。

## 升级与使用提醒

- 使用原 `deploy.sh`，沿用已有安装目录、数据目录与服务名，保留配置、聊天、记忆和战役存档；不要用插件同步脚本更新宿主。
- PDF 需要 Python 3 + Pillow，可复用 JM 配置的 Python 环境，不要求开启 JM。原实例的 PID 默认发送方式保留，可手动改为 PDF。
- PID 下载缓存默认启用并受期限和容量限制；清理缓存不删除分级、配置、历史或 JM 文件，关闭功能后已有缓存仍按规则清理。
- 独立东京代理／图片服务须按文档另行安装或更新，升级宿主不会自动更新这些服务。已有服务也需要同步新版，才能使用本版的连接与压缩优化。
- Google Lens 验证码问题仍未解决，东京出口不能保证免验证；以图搜图可切换 Yandex 或 trace.moe。
- 发布工作流通过 Linux 语法、静态扫描、单元、本地回归、PDF 与前端检查后发布；Windows 全量测试仍有既有平台差异，不宣称跨平台全量全绿。
